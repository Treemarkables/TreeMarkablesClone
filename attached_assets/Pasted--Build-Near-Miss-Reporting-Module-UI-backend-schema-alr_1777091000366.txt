  ## Task 1 — Backend routes in `server/routes.ts`                                                                                               
  Add CRUD endpoints. Mirror the patterns of existing route blocks (e.g. the `/api/vehicle-inspections` routes around line 21691 are a good      
  template).                                                                                                                                     
                                                         
  Endpoints needed:                                                                                                                              
  - `GET    /api/near-miss-reports` — list with filters (status, severity, category, dateFrom/dateTo, reporterUserId)
  - `GET    /api/near-miss-reports/:id` — full report including attachments, witnesses, actions                                                  
  - `POST   /api/near-miss-reports` — create draft. Server generates `reportNumber` as `NM-YYYY-####` (sequential within year)                   
  - `PUT    /api/near-miss-reports/:id` — update (any field except reportNumber)                                                                 
  - `POST   /api/near-miss-reports/:id/submit` — sets status=submitted, submittedAt=now, effectivenessReviewDate=now+30d                         
  - `DELETE /api/near-miss-reports/:id` — drafts only, blocked once submitted                                                                    
  - `POST   /api/near-miss-reports/:id/attachments` — multipart upload, stores file in `/uploads/near-miss/{report_id}/`. Use whatever upload    
  pattern already exists (search `server/routes.ts` for existing upload endpoints — likely under `/api/jobs/.../photos` or similar)              
  - `DELETE /api/near-miss-attachments/:id`                                                                                                      
  - `POST   /api/near-miss-reports/:id/witnesses` — create witness record                                                                        
  - `POST   /api/near-miss-witnesses/:id/sign` — accepts signatureSvg, witnessComment, lat, lng, device. Server computes SHA-256 of report       
  content and stores in reportHashAtSigning.                                                                                                     
  - `POST   /api/near-miss-witnesses/:id/decline` — sets status=declined                                                                         
  - `POST   /api/near-miss-reports/:id/actions` — create corrective action                                                                       
  - `PUT    /api/near-miss-actions/:id` — update (status, completedAt, etc)                                                                      
  - `DELETE /api/near-miss-actions/:id`                                                                                                          
                                                                                                                                                 
  Use `AuthenticatedRoute`-equivalent middleware on the server side (whatever pattern existing routes use — staff/crew need access, not just     
  admin).

  ## Task 4 — Build `client/src/pages/NearMissReport.tsx` (3-step capture flow, mobile-first)                                                    
                                                         
  ### Step 1 — Capture                                                                                                                           
  - Header: "Report near miss" + "CONFIDENTIAL" badge    
  - Quick row: Take photo (camera input), Voice note (browser-native `SpeechRecognition` API for live dictation; transcribed text auto-fills the 
  description textarea below)                                                                                                                    
  - Severity selector: 4 buttons — Low (green), Medium (blue), High (amber), Critical (red)                                                      
  - Category dropdown (values from schema enum)                                                                                                  
  - Description textarea                                 
  - Auto-filled read-only block: location (geolocation API), job number (if launched from a job), reporter name (from `useAuth`), timestamp      
  - Continue button → Step 2                                                                                                                     
                                                                                                                                                 
  ### Step 2 — Causes & Action                                                                                                                   
  - Equipment involved — multi-select chips (chainsaw, bucket truck, chipper, stump grinder, mini loader, rigging, ropes, MEWP, vehicles)        
  - Contributing factors — multi-select chips (communication, fatigue, weather, planning, training, equipment, other)                            
  - People involved — searchable user picker (fetch from `/api/users` or equivalent existing endpoint) + free-text for non-staff                 
  - Immediate action taken — textarea                                                                                                            
  - Proposed control — textarea                                                                                                                  
  - Corrective actions — repeatable block: title, controlType select, assignee picker, due date                                                  
  - Toggle: "Share at next toolbox talk" (default ON, sets `toolboxTalkFlag`)                                                                    
  - Continue button → Step 3                                                                                                                     
                                                                                                                                                 
  ### Step 3 — Witness sign-off                                                                                                                  
  - Three-state radio:                                   
    1. Witnessed & signing now                                                                                                                   
    2. Witness named, sign later                         
    3. No witness / sole worker (flags for supervisor review)                                                                                    
  - If state 1 or 2: witness picker (user search + free-text fallback) + comment textarea                                                        
  - If state 1: signature panel                                                                                                                  
    - Read-only summary card (severity badge, category, location, description excerpt)                                                           
    - Declaration checkbox: "I confirm I witnessed this incident and the account above is accurate to the best of my knowledge."                 
    - Signature canvas — copy the canvas pattern from `client/src/pages/VehicleInspection.tsx:303-362` (mouse + touch, exports SVG path data NOT 
  base64). DO NOT add `react-signature-canvas` as a dependency.                                                                                  
    - Locked metadata block: timestamp, GPS lat/lng, device user-agent                                                                           
    - Submit button → POSTs to `/api/near-miss-reports/:id/submit` then `/api/near-miss-witnesses/:id/sign`                                      
  - If state 2 or 3: Submit button → POSTs `/submit` only
