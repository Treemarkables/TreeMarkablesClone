1. Platform Overview

The Treemarkables Job Management Platform is a comprehensive, mobile-first business management system built specifically for New Zealand-based arborist and tree service companies. It is built on a modern web stack (React + Node.js + PostgreSQL) and includes a native iOS app via Apple Capacitor.

What the platform does

ModuleCapability
Job ManagementFull job lifecycle — leads, quotes, proposals, scheduling, dispatch, completion, invoicing. Dispatch board with ServiceM8-style layout. AI-powered smart scheduling.
Customer & SalesLead tracking, customer CRM, VIP membership, quote builder, interactive proposals with customer option selection, conversion analytics.
SchedulingAI Smart Dispatch (GPT-4o), staff licence matching, equipment licence checks, daily revenue targeting, Google Calendar sync.
CommunicationsSMS (SMS Everyone NZ), transactional email (Resend), Gmail reply capture, Twilio voice calls + call recording, AI-generated quote messages.
Crew & EquipmentStaff management, licence/ticket tracking, equipment register, pre-start vehicle inspections, time tracking with charge-out rates.
Invoicing & AccountingInvoice builder, line items from time tracking, Xero sync, GST-inclusive pricing in NZD.
MarketingMailchimp customer sync, Meta (Facebook/Instagram) ad campaign manager, automated review posting, marketing planner.
AI FeaturesAI chat assistant (GPT-4o with live business data), speech-to-quote (Whisper), AI dispatch, AI text extraction from Facebook messages.
NotificationsPush notifications via Firebase (job assignments, schedule changes, new leads, invoice payments), SMS alerts, email alerts.
iOS AppNative iOS app via Capacitor — CallKit integration with Twilio, push notifications via APNs/FCM, camera access, PWA install.
OperationsRoute optimisation, weather integration, mulch drops tracker, safety reporting, job diary, photo documentation.

Target subscriber

NZ-based arborist or tree service businesses with 2–20 staff. Ideally owner-operated businesses wanting to replace paper-based, spreadsheet, or ServiceM8 workflows with a purpose-built system.

2. Subscription & Infrastructure Model

How the platform is hosted

The platform currently runs as a single-tenant deployment per subscriber — each subscriber gets their own isolated environment with their own database and API credentials. This means there is no data co-mingling between subscribers, and each subscriber's credentials are fully separate.

ℹ️
Current Architecture: Single codebase deployed per subscriber using environment variables to isolate credentials. Future versions may move to a multi-tenant architecture with shared hosting and per-subscriber database schemas.

What you manage centrally (Platform Owner)

  • The codebase and deployments (Replit or other hosting)
  • The iOS app on Apple App Store / TestFlight (one app, subscriber logs in)
  • OpenAI API key (shared or per-subscriber with usage limits)
  • Firebase project (one project, one service account, all subscriber devices register under it)
  • Addy.co.nz API key (can be shared — rate limits per key)
  • Resend sending domain (centralised domain, subscriber gets their own from-address)
  • Platform support, updates, and bug fixes

What is set up per subscriber

  • PostgreSQL database (separate Neon project)
  • Xero Custom Connection (subscriber's own Xero organisation)
  • SMS Everyone account (subscriber's business name as Sender ID)
  • Twilio subaccount with a dedicated NZ phone number
  • Gmail account for reply capture (or subscriber's own Gmail)
  • Mailchimp audience (if subscriber uses email marketing)
  • Meta page access token (if subscriber uses Facebook/Instagram marketing)
  • Google Calendar OAuth (subscriber's own Google account)

Xero Accounting

Optional — Pro+ tier

Purpose: Syncs invoices, creates/matches customer contacts in Xero, pushes job invoices as accounts receivable (ACCREC) invoices. Uses Xero Custom Connection (machine-to-machine, no user OAuth required).

ItemDetail
Account typeSubscriber must have an active Xero organisation subscription (they pay Xero separately)
Who createsYou set up the Custom Connection app in the subscriber's Xero Developer Portal
Credentials neededXERO_CLIENT_ID, XERO_CLIENT_SECRET
Token typeClient Credentials (expires every 30 minutes — auto-refreshed by the platform)
Cost to you$0 — Xero API access is free. Subscriber pays Xero for their plan (~$50–100/month).
Setup time20 minutes

Setup steps

  1. Log in to developer.xero.com using the subscriber's Xero account
  2. Go to My Apps → New App
  3. Select Custom Connection (not standard/partner)
  4. Grant scopes: accounting.contacts accounting.transactions accounting.settings (add payroll scopes if needed)
  5. Copy Client ID and Client Secret into the subscriber's environment
  6. In the platform Settings → Xero, click "Connect to Xero" to verify the connection
  7. Set the Xero Sales Account Code (default: 200) and Tax Type (default: OUTPUT2 for 15% GST)
⚠️
Custom Connection tokens expire every 30 minutes. The platform auto-refreshes them. However, if the XERO_CLIENT_ID/XERO_CLIENT_SECRET are rotated or the scopes change in Xero Developer Portal, you must hit the "Refresh Token" button in Settings → Xero to get a new token with updated scopes.

Twilio (Voice & Call Recording)

Optional — Pro+ tier

Purpose: Provides a dedicated NZ phone number for the subscriber. Customer calls are forwarded to Twilio, which records the call, transcribes it via Whisper AI, and optionally rings the iOS app via CallKit (Twilio Voice SDK). The subscriber's personal mobile rings via carrier forwarding — customers never know Twilio is involved.

ItemDetail
Account typeTwilio main account or subaccount (recommended: one subaccount per subscriber)
Who createsPlatform owner (you) — create a Twilio subaccount under your main account
Credentials neededTWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_API_KEY, TWILIO_API_KEY_SECRET, TWILIO_PHONE_NUMBER, TWILIO_TWIML_APP_SID
NZ phone number cost~$2.50 USD/month for a local NZ number
Voice call cost~$0.013 USD/minute to receive calls
Call recordingIncluded — stored in Twilio for 90 days by default
Setup time45–60 minutes

Setup steps

  1. Log in to twilio.com/console → Create a Subaccount for the subscriber
  2. Note the subaccount SID and Auth Token
  3. Buy a New Zealand phone number in the subaccount
  4. Create an API Key & Secret (recommended over Auth Token for production)
  5. Create a TwiML App with the platform's voice webhook URL: https://[subscriber-domain]/api/twilio/voice
  6. Note the TwiML App SID
  7. Set all credentials in the subscriber's environment
  8. In Settings → Business, enter the subscriber's personal phone number for call forwarding
  9. Subscriber sets up carrier call forwarding: personal mobile → Twilio NZ number
🔴
Important: The Twilio webhook secret (HERO_WEBHOOK_SECRET in the current deployment) must be set to validate Twilio webhook signatures. Do not skip this step.

Resend (Transactional Email)

Required

Purpose: Sends all outgoing emails — quote/proposal emails, invoice emails, booking confirmations, general customer communications. Emails are sent from a verified domain (e.g. info@updates.treemarkables.co.nz) with the subscriber's business name as the sender.

ItemDetail
Account typeResend.com account — free up to 3,000 emails/month and 100/day
Who createsPlatform owner (you) — can use a single Resend account with multiple sending domains
Credentials neededRESEND_API_KEY
Domain verificationAdd DNS records to the subscriber's sending domain (e.g. updates.subscriberdomain.co.nz)
Free tier3,000 emails/month — sufficient for most small subscribers
Paid tier~$22 NZD/month for 50,000 emails/month (Pro plan)
Setup time15 minutes (plus DNS propagation: up to 48 hours)

Setup steps

  1. Log in to resend.com → Add a Sending Domain for the subscriber
  2. Add the provided DNS records (TXT + MX) to the subscriber's domain registrar
  3. Wait for DNS propagation (usually 15–60 minutes, up to 48 hours)
  4. Verify the domain in Resend dashboard
  5. Create an API key scoped to the verified domain
  6. Update the fromEmail value in server/resendClient.ts with the subscriber's business name and domain
  7. Set RESEND_API_KEY in subscriber environment

Gmail (Email Reply Capture)

Required

Purpose: The platform monitors a Gmail inbox via IMAP and automatically captures customer email replies. Captured replies are logged to the relevant job diary as diary entries, and linked to the customer record. Outgoing emails can also be sent via Gmail/SMTP as a fallback.

ItemDetail
Account typeStandard Gmail or Google Workspace account
Who createsSubscriber (their own Gmail), or you create a dedicated platform Gmail for them
Credentials neededGMAIL_USER (email address), GMAIL_APP_PASSWORD (16-character App Password)
2FA requirementGoogle account must have 2-Factor Authentication enabled before App Password can be generated
CostFree (standard Gmail) or from $8 USD/month for Google Workspace
Setup time10 minutes

Setup steps

  1. Log in to myaccount.google.com with the subscriber's Gmail account
  2. Go to Security → 2-Step Verification → Enable it
  3. Go to Security → App passwords → Create a new App Password
  4. Select App: "Mail", Device: "Other (Custom name)" → enter "Treemarkables Platform"
  5. Copy the 16-character App Password
  6. Set GMAIL_USER = Gmail address, GMAIL_APP_PASSWORD = App Password in subscriber environment
  7. Enable IMAP in Gmail Settings → See All Settings → Forwarding and POP/IMAP → Enable IMAP

Firebase Cloud Messaging (Push Notifications)

Required

Purpose: Sends real-time push notifications to the iOS (and Android) app — job assignments, schedule changes, new leads, invoice payments, quote acceptances. Uses Firebase Admin SDK with a service account JSON.

ItemDetail
Account typeFirebase project (console.firebase.google.com) — can be shared across subscribers
Who createsPlatform owner — one Firebase project for all subscribers (or per-subscriber for isolation)
Credentials neededFIREBASE_SERVICE_ACCOUNT (full JSON service account as a single-line string)
APNs keyApple Push Notification service key must be uploaded to Firebase for iOS notifications
CostFirebase Spark (free) plan supports up to 1M notifications/month. Sufficient for all small subscribers.
Setup time30 minutes

Setup steps

  1. Go to console.firebase.google.com → Select or create a project
  2. Go to Project Settings → Service Accounts → Generate new private key
  3. Download the JSON file → minify it to a single line (remove newlines except in private_key)
  4. Set as FIREBASE_SERVICE_ACCOUNT in subscriber environment
  5. Go to Project Settings → Cloud Messaging → Apple app configuration
  6. Upload the APNs authentication key (Key ID D44XQ29XZM, Team ID 7Q57T2KAH9 for current deployment)
  7. Register the iOS app with bundle ID com.treemarkables.app
⚠️
The APNs key is linked to the Apple Developer account. If you onboard a subscriber with a different bundle ID, you need a new Firebase app registration and potentially a new APNs key. APNs keys do not expire but can be revoked — keep them secure.

What to do when Xero token fails

  1. Go to platform Settings → Xero
  2. Click "Disconnect" → then "Connect to Xero" again
  3. If scopes have changed: click "Refresh Token" and check the scopes shown
  4. If credentials have been regenerated: update XERO_CLIENT_ID and XERO_CLIENT_SECRET in the subscriber's environment and restart the server

Platform update process

  1. Test the update in your own development environment first
  2. If schema changes are included, prepare migration instructions
  3. Deploy to each subscriber's environment (Replit: pull latest → restart)
  4. Run npm run db:push if there are schema changes
  5. Notify subscribers of any changes that affect their workflow

SMS credit monitoring

SMS Everyone credits are pre-purchased and will run out without warning. To avoid service disruption:

  • Check credit balance monthly via the SMS Everyone dashboard or API (/api/credits)
  • Set a low-balance email alert in the SMS Everyone account settings
  • Include SMS credits in your subscriber monthly fee (pre-purchase on their behalf) or bill them separately when credits run low

iOS app updates & TestFlight

  • Build a new iOS binary when significant updates are ready: npm run build → npx cap sync ios → Archive in Xcode → Upload to App Store Connect
  • TestFlight builds expire after 90 days — upload a new build before expiry
  • App Store review required for public releases (1–3 days). TestFlight builds available within hours.
  • For emergency patches, TestFlight is the fastest path — invite testers and distribute without App Store review

Address territory configuration

The address autocomplete is currently configured to search Gisborne territory only. When onboarding a subscriber in a different region:

  • Edit server/services/addressService.ts line 27 — change territory=Gisborne to the subscriber's region or remove the parameter for nationwide search
  • Valid NZ territories include: Auckland, Wellington, Canterbury, Waikato, Bay of Plenty, Manawatu-Whanganui, Otago, Gisborne, Nelson, Hawke's Bay, Taranaki, Southland, Marlborough, West Coast, Tasman
